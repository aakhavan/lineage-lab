# L1: The two stacks and the OpenMetadata client

Contract: `docs/spec.md` section 2. Rules: `AGENTS.md`.

Build:
1. `stack/openmetadata/docker-compose.yml`: the OpenMetadata 2.0.5 Postgres quickstart compose file, downloaded from the release URL in the spec and saved unchanged except for a first comment line with the URL and today's date. Compose project `lineagelab_om`.
2. `stack/marquez/docker-compose.yml`: Marquez API, web UI and its own Postgres with pinned image tags (check the Marquez repository for the current ones). Compose project `lineagelab_marquez`. If a default port is taken on this machine, move it and record it.
3. `stack/versions.yaml`: every image tag, every tool version and the URLs and ports in use. Later steps add their tools here.
4. `src/lineagelab/stack.py`: `python -m lineagelab.stack up|down|status [--only om|marquez]` as the spec says (`up` waits for health, `down` keeps volumes, `status` prints one JSON line).
5. `src/lineagelab/om.py`: `client()`, `get`, `put`, `post`, `table(fqn)`, `upstream(fqn, depth=3)` as the spec says. Find the real API calls for the admin login and the `ingestion-bot` token in the running server's own API docs (Swagger on the server) and note them in `NOTES.md`. The token stays in memory.
6. Start both stacks and leave them running for the next steps.

Tests (offline, `tests/`): `test_status_line_shape`, `test_compose_files_name_their_projects`, `test_versions_file_lists_every_image_in_the_compose_files`, `test_table_and_upstream_reshape_api_payloads` (on small hand-made payloads saved as fixtures from what the real API returned, with ids and emails removed).

Done when `plan/accept/accept_l1.py` passes (it needs both stacks up).
