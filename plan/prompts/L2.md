# L2: Work copy, dbt build with artifacts, and the database in OpenMetadata

Contract: `docs/spec.md` sections 1 and 3. Rules: `AGENTS.md`. Both stacks from L1 and the governor test bed must be up (`python -m lineagelab.stack status`; the test bed is started only by its own compose file, see the spec, and never changed).

Build:
1. `src/lineagelab/workcopy.py`: `python -m lineagelab.workcopy` copies `../olist-dbt` (env `LAB_DBT_PROJECT` overrides the path) to `work/olist-dbt/` without `target/`, `logs/` and `.git`; replaces an older copy; prints one JSON line (files copied).
2. `src/lineagelab/dbtrun.py`: `python -m lineagelab.dbtrun build` runs `dbt build` then `dbt docs generate` on the work copy, target `dev`, with the project's own `profiles/`; dbt in an isolated environment (dbt-core 1.12, dbt-postgres); logs to `logs/`; one JSON line: models, tests passed, tests failed, artifacts present. A failing dbt test is reported, not hidden.
3. `src/lineagelab/ingest.py`: `python -m lineagelab.ingest database` registers the Postgres service `shop_testbed` and runs the metadata ingestion for database `shop`, schemas `raw`, `dev_governor`, `analytics` only, with sample data and profiling off. The workflow YAML is rendered by a pure function and written to `work/ingest/database.yaml`. Try `docker exec` in the ingestion container first (host `host.docker.internal`, port 55432), then the `uvx` fallback; record which one works in `stack/versions.yaml` and `NOTES.md`.
4. Run all three and leave the result in OpenMetadata.

Tests (offline): `test_workcopy_skips_target_logs_and_git`, `test_database_workflow_yaml_has_only_the_three_schemas`, `test_database_workflow_yaml_turns_sample_data_off`, `test_rendered_yaml_in_tests_holds_no_real_credentials`.

Done when `plan/accept/accept_l2.py` passes.
